## 执行摘要

成功修复了 RavBot 中的 "Improperly formed request" 错误。问题根源是 `narrow_anthropic_tools_for_replay()` 函数在重试请求时缩减工具列表,导致工具列表与系统提示词不匹配,Anthropic API 拒绝请求。

## 根本原因分析

### 1. 请求流程

1. **第一次请求**: LLM 调用 `github_get_repo` 和 `web_search` 工具
2. **工具执行**: 两个工具都成功执行并返回结果
3. **第二次请求**: 系统准备发送工具结果给 LLM
4. **问题发生**: `narrow_anthropic_tools_for_replay()` 被调用

### 2. 问题代码

**位置**: `src/core/agent_loop.cpp:883-902`

```cpp
static void narrow_anthropic_tools_for_replay(
    ChatCompletionRequest& request,
    const std::unordered_set<std::string>& matched_tool_names) {
  if (matched_tool_names.empty()) {
    return;
  }

  std::vector<nlohmann::json> filtered_tools;
  filtered_tools.reserve(request.tools.size());
  for (const auto& tool : request.tools) {
    const auto tool_name = extract_tool_schema_name(tool);
    if (!tool_name.empty() && matched_tool_names.count(tool_name) > 0) {
      filtered_tools.push_back(tool);
    }
  }

  if (!filtered_tools.empty()) {
    request.tools = std::move(filtered_tools);  // ❌ 问题在这里!
  }
}
```

### 3. 问题链条

```
初始状态:
- request.tools: 21 个工具
- system prompt: 列出所有 21 个工具
    ↓
narrow_anthropic_tools_for_replay() 被调用
    ↓
检测到 web_search 已被使用
    ↓
过滤工具列表,只保留已使用的工具
    ↓
结果状态:
- request.tools: 1 个工具 (github_get_repo)
- system prompt: 仍然列出 21 个工具  ❌ 不匹配!
    ↓
Anthropic API 检测到不一致
    ↓
返回 HTTP 502: "Improperly formed request"
```

### 4. 错误 Payload 分析

**文件**: `/tmp/ravbot_error_payload.json`

```json
{
  "tools": [
    {
      "name": "github_get_repo",
      "description": "...",
      "input_schema": {...}
    }
  ],  // ❌ 只有 1 个工具
  "system": "...Available Tools...\n- **read**: ...\n- **write**: ...\n- **exec**: ...\n...(列出 21 个工具)..."  // ❌ 系统提示词列出 21 个工具
}
```

**不一致**:
- `tools` 数组: 1 个工具
- `system` 提示词: 21 个工具

## 解决方案

### 修复方法

禁用 `narrow_anthropic_tools_for_replay()` 函数,保持工具列表完整。

**修改文件**: `src/core/agent_loop.cpp:883-902`

**修改前**:
```cpp
static void narrow_anthropic_tools_for_replay(
    ChatCompletionRequest& request,
    const std::unordered_set<std::string>& matched_tool_names) {

  }

  std::vector<nlohmann::json> filtered_tools;
  filtered_tools.reserve(request.tools.size());
  for (const auto& tool : request.tools) {
    const auto tool_name = extract_tool_schema_name(tool);
    if (!tool_name.empty() && matched_tool_names.count(tool_name) > 0) {
      filtered_tools.push_back(tool);
    }
  }

  if (!filtered_tools.empty()) {
    request.tools = std::move(filtered_tools);
  }

```

**修改后**:
```cpp
static void narrow_anthropic_tools_for_replay(
    ChatCompletionRequest& request,
    const std::unordered_set<std::string>& matched_tool_names) {
  // DISABLED: This function causes "Improperly formed request" errors
  // when it narrows the tool list but the system prompt still lists all tools.
  // The mismatch between system prompt (21 tools) and actual tools (1 tool)
  // causes Anthropic API to reject the request with HTTP 502.
  //
  // Root cause: When web_search is detected in history, this function filters
  // tools to only include previously-used tools (e.g., github_get_repo).
  // But the system prompt generated by build_system_prompt() still lists all
  // 21 available tools, creating an inconsistency.
  //
  // Solution: Keep all tools in the request to match the system prompt.
  // The web_search replay hint is sufficient to guide the LLM behavior.
  return;

  /* ORIGINAL CODE - DISABLED
  ... (原始代码被注释)
  */
}
```

### 为什么这样修复?

1. **保持一致性**: 工具列表和系统提示词保持一致
2. **保留功能**: `web_search replay hint` 仍然有效,可以指导 LLM 不要重复调用 web_search
3. **最小影响**: 只禁用有问题的功能,不影响其他部分

## 设计讨论

### 原始设计意图

`narrow_anthropic_tools_for_replay()` 的设计目的是:
1. 减少 payload 大小
2. 优化 API 调用成本
3. 提高响应速度

### 为什么失败?

1. **不完整的实现**: 只修改了工具列表,没有同步更新系统提示词
2. **假设错误**: 假设 Anthropic API 不会验证工具列表和系统提示词的一致性
3. **测试不足**: 没有测试 replay 场景下的请求格式

### 正确的实现方式

如果要实现工具列表优化,需要:
1. **同步更新系统提示词**: 当缩减工具列表时,也要更新系统提示词中的工具列表
2. **完整性验证**: 在发送请求前验证工具列表和系统提示词的一致性
3. **充分测试**: 测试所有 replay 场景

但这样的实现复杂度很高,收益有限 (只节省 5KB),因此当前的解决方案 (禁用功能) 是最合理的。

### 问题 2: 是否会影响其他功能?

**答案**: ❌ 不会

`narrow_anthropic_tools_for_replay()` 只在特定场景下被调用:
- 检测到 web_search 在历史中
- Anthropic provider
- 重试请求时

禁用它不会影响:
- 首次请求
- 其他工具的使用
- 其他 provider (OpenAI, Ollama, etc.)

**答案**: ❌ 不需要
