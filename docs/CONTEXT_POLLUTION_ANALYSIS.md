# RavBot 上下文污染问题分析报告

## 问题描述

用户报告在多轮对话后,RavBot 出现答非所问的问题:
- 用户要求:"我需要你帮我找github上的obsidian相关的长效记忆"
- RavBot 实际搜索:"你有什么技能?"(一个旧问题)

## 根本原因

通过分析实际运行日志(`/home/rogers/.ravbot/logs/ravbot_2026-03-12.log`),发现:

### 1. LLM 收到的上下文过长
完整对话历史包含:
- "你有什么技能?" (问了3次)
- "跨境电商网站开发"
- "今天有什么重要新闻?"
- "长效记忆"相关讨论
- "Obsidian 接入"
- "会议总结"
- "列出已安装的技能"
- 最后:"我需要你帮我找github上的obsidian相关的长效记忆"

### 2. 用户使用了模糊指令
用户说"你帮我搜索",没有明确指定搜索什么,LLM 需要从上下文推断。

### 3. LLM 选择了错误的搜索意图
由于上下文中"你有什么技能?"出现了多次,LLM 错误地认为用户想搜索这个问题。

### 4. 现有上下文裁剪不够智能
当前的 `trim_anthropic_replay_to_current_turn` 只在**工具续轮**(最后一条消息是 tool_result)时触发,但在用户发送新问题时不会触发。

## 日志证据

```
[2026-03-12 17:11:16.310] [debug] Received response from Anthropic API:
...
"content_block":{"content":[{"encrypted_content":"If you have any suggestions...
"title":"有什么建议 - Translation into English - examples Chinese"
```

这证明 LLM 搜索的是 "你有什么技能?" 的翻译,而不是 obsidian 相关内容。

## 解决方案

### 方案 1: 增强上下文裁剪(已实现)
- ✅ 为所有 provider 应用上下文裁剪
- ✅ 在工具续轮时裁剪旧历史
- ❌ 但这不够,因为问题发生在新问题时,不是工具续轮时

### 方案 2: 智能上下文窗口管理(推荐)
需要实现:
1. **相关性评分** - 根据新问题评估历史消息的相关性
2. **动态裁剪** - 只保留与当前问题相关的历史
3. **意图明确化** - 当用户使用模糊指令时,要求明确

### 方案 3: 改进 System Prompt
在 system prompt 中明确指示:
- 当用户说"搜索"时,必须明确搜索什么
- 如果不清楚,应该询问用户而不是猜测
- 优先使用最近的上下文,而不是旧的对话

## 测试结果

### 单元测试
✅ 945/945 测试通过
- ContextPollutionTest: 通过
- ComprehensiveContextTest: 通过
- AgentLoopTest.AnthropicReplay*: 通过

### 实际运行测试
❌ 仍然出现答非所问
- 原因:测试场景与实际使用场景不同
- 测试中 LLM 是 mock 的,不会出现意图理解错误
- 实际运行中 LLM 需要从复杂上下文中推断意图

## 建议

### 短期(立即可做)
1. **改进 System Prompt** - 明确指示 LLM 在不确定时询问用户
2. **用户教育** - 建议用户使用明确的指令,如"搜索 obsidian 长效记忆"而不是"你帮我搜索"

### 中期(需要开发)
1. **实现智能上下文裁剪** - 根据相关性动态裁剪历史
2. **添加意图确认机制** - 当 LLM 不确定时,先确认再执行

### 长期(架构改进)
1. **实现向量检索** - 使用 embedding 找到最相关的历史上下文
2. **会话分段** - 自动识别话题转换,创建新的上下文段

## 结论

上下文裁剪逻辑本身是正确的,但:
1. **触发时机不对** - 只在工具续轮时触发,新问题时不触发
2. **裁剪策略不够智能** - 简单地保留最近的消息,而不是最相关的消息
3. **LLM 意图理解** - 当用户使用模糊指令时,LLM 容易从错误的上下文中推断意图

需要从多个层面改进:代码逻辑、System Prompt、用户交互方式。
